# 後台使用說明

給三個月後忘記怎麼操作的自己。

---

## 開啟

```bash
npm run dev
```

然後開 **http://localhost:5173/admin**

後台只存在於本機。線上的 `novie131.github.io/admin` 是 404，因為它從來沒被打包進去 —— 這也是為什麼它不需要密碼。

它的安全性來自「production 不存在這個東西」，不是來自「沒人知道它存在」，所以這份文件公開在 repo 裡並不構成風險（後台的原始碼本來就在 `src/admin/` 和 `plugins/admin-api.js`，公開可讀）。真正要留意的是另一件事：**dev server 開著的時候，你在同一個瀏覽器逛到的網站可以對 localhost 送請求**。`/__admin/*` 已經加上同源檢查，跨來源請求一律 403 —— 但這也是為什麼平常不用時就把 dev server 關掉比較好。

## 日常流程

改任何內容都是同樣三步：

```
1. 在後台改 → 按「儲存這一頁」      （寫進 src/content/*.json）
2. git add -A && git commit -m "..."
3. git push                          （約 1 分鐘後上線）
```

**第 2、3 步不做就不會上線。** 後台只是幫你改本機檔案，不是幫你發布。

推完可以去 repo 的 Actions 分頁看 workflow 跑完沒，或直接開網站按 Ctrl+F5 硬重新整理。

## 六個分頁

| 分頁 | 對應檔案 | 型態 |
| --- | --- | --- |
| 作品集 | `src/content/projects.json` | 表單 |
| 履歷 | `src/content/resume.json` | 表單 |
| 關於 | `src/content/about.json` | JSON 編輯器 |
| 聯絡 | `src/content/contact.json` | JSON 編輯器 |
| 首頁 | `src/content/home.json` | JSON 編輯器 |
| 圖片 | `public/img/` | 上傳／複製網址／刪除 |

分頁標籤上出現小藍點 = 那一頁有未儲存的修改。切換分頁不會弄丟草稿，但**關掉瀏覽器會**（會跳確認視窗提醒）。

儲存是分頁各自獨立的：在作品集按儲存，只會寫 `projects.json`。

## 常見任務

### 新增一個作品

作品集分頁 →「+ 新增作品」→ 填欄位 → 儲存。

- **分類** 要能被上方「篩選分類」的字串命中才會被篩到。例如分類填 `AI / DevTools`，篩選有 `AI` 就抓得到（用的是包含比對）。
- **描述、功能重點** 中英各一欄，兩邊都要填，否則切到另一個語言會空掉。
- **功能重點、技術標籤** 是一行一項，不用加符號。
- **Demo 連結** 沒有就留空，卡片上不會出現那顆按鈕。
- **封面圖** 留空的話卡片就純文字，不會有破圖。

### 補上證照的 credential ID

履歷分頁 → 找到那張證照 → 填 `Credential ID` 和 `驗證連結` → 儲存。

兩個欄位都是留空就不顯示。填了連結，卡片才會出現「驗證 →」按鈕 —— 招募方會點，這比多列一張證照有用。

### 新增競賽紀錄

履歷分頁 → 競賽區 →「+ 新增」。

目前是空的，所以整個競賽區塊不會出現在網站上。加第一筆之後才會冒出來。`resume.json` 裡有一份 `_competitionSchema` 是欄位說明，不會被渲染，可以留著。

### 換頭像

1. 圖片分頁 → 拖圖上傳 → 複製網址（例如 `/img/me-mtayf3xp.webp`）
2. 首頁分頁 → 把最上面 `"avatar"` 的值換成剛剛複製的網址 → 儲存

頭像在網站上只顯示 64×64，上傳什麼尺寸都會被壓到 1600px 以內，不必自己先處理。

### 換分享用的預覽圖（OG image）

這個**不走後台**。直接換掉 `public/og.png`，必須是 **1200×630 的 PNG**，因為 `index.html` 裡寫死了尺寸宣告。換完可以用 [opengraph.xyz](https://www.opengraph.xyz/) 貼網址驗證。

## 圖片規則

上傳時 dev server 會自動做三件事，所以**手機直接拍的照片可以直接丟**：

1. 依 EXIF 轉正（不然直式照片會躺著）
2. 限制最大寬度 1600px
3. 轉成 WebP（品質 82）

檔名會被正規化並加上時間戳，例如 `我的照片.PNG` → `-mtayf3xp.webp`。原檔不會保留，要留就自己另外存一份到 `assets-src/`（那個資料夾只留本機，不會進版控也不會被部署）。

**刪除前先確認沒有地方在引用**，後台不會幫你檢查。刪掉還在用的圖，網站上就是破圖。

## 容易踩的雷

- **儲存 ≠ 上線。** 一定要 commit + push。
- **JSON 編輯器格式錯誤時存不進去**，下方會紅字說哪裡錯。通常是多打或少打逗號。
- **留空要用 `null`，不要用空字串。** 表單欄位清空會自動存成 `null`，但在 JSON 編輯器裡手動填 `""` 的話，程式會判定「有值」而渲染出一個空元素。
- **清單留空陣列 `[]` 是安全的** —— 整個區塊會消失，不會留下一個空標題。
- **雙語欄位只填中文**，切到英文版就會是空白。
- **新增「頁面」（不是新增內容）要同步改三個地方**，否則新頁面沒有自己的 meta，而且直接開網址會 404：
  1. `src/App.jsx` 的 `<Route>`
  2. `src/hooks/usePageMeta.js` 的 `ROUTE_META`
  3. `scripts/postbuild.mjs` 的 `ROUTES`（順便更新 `public/sitemap.xml`）

## 出問題時

| 症狀 | 原因 / 處理 |
| --- | --- |
| 開 `/admin` 一片空白 | dev server 沒跑，或還在編譯。等幾秒重整 |
| 儲存跳「存檔失敗」 | 看終端機的 Vite 輸出，通常是 JSON 結構不對 |
| 圖片上傳失敗 | 超過 20 MB 上限，或不是圖片檔 |
| 網站上沒看到改動 | 忘了 push；或 Actions 還在跑；或瀏覽器快取（Ctrl+F5） |
| build 掛掉 | 先跑 `npm run lint` 和 `npm run build` 看錯誤訊息，多半是 JSON 被手動改壞 |

改壞了想回到上一個狀態：`git checkout src/content/` 就會把所有內容檔還原成上次 commit 的樣子。
